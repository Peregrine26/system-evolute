## 五个必须能讲清的点

**1. 界面为什么不自己存"窗口在哪"？**
界面拿到的是一份快照（`QVector<WindowItem>`），每次刷新整份替换。窗口位置、能不能操作，都由服务说了算。界面只额外记一件服务不关心的事：**哪个窗口上次失败了、失败原因是什么**（`m_failures`）。这不构成"第二份真相"，因为它只在收到结果信号时写入。

**2. 为什么命令不返回 bool？**
`placeWindow()` 是 `void`，结果走 `operationFinished(OperationResult)`。因为真实实现是系统调用：`SetWindowPos` 返回 true 只代表"调用发出了"，窗口可能被系统拒绝。两个窗口里失败一个，只有逐窗回报才说得清是哪一个——这就是 `OperationResult.window` 的用途。

**3. 最多两个窗口，勾第三个为什么是"替换"而不是"不响应"？**
`onItemChanged` 里判断 `m_checked.size() >= 2`，取最早的那个取消勾选，并在状态栏说明。理由：点了没反应，用户会以为程序卡了；静默拒绝比明确替换更糟。

**4. 画面切换动画期间为什么要禁用按钮？**
`fadeScene()` 里设 `m_animating = true` 并禁用操作条上的按钮。否则连点两下"确认排列"会发两轮命令；第一轮还没回来，第二轮又发出去，最后状态栏显示的是哪一轮都说不清。这是 M4 的硬要求："动画中按钮不会重复触发操作"。

**5. 为什么 Enter 没有单独注册 QShortcut？**
`QListWidget` 自己会把回车解释成"激活当前项"并发出 `itemActivated`。再注册一个 `QShortcut(Return)` 会和它抢同一个按键，出现一次回车发两条命令。所以 Enter 走 `itemActivated`，其余三个键走 `QShortcut`。

## 失败路径（老师最爱问）

| 场景 | 界面怎么表现 |
| --- | --- |
| 定位被系统拒绝 | 状态栏红字写明原因，该行末尾加 `! 原因` |
| 排列时某个窗口失败 | 逐个 `OperationResult` 记录，回总览后该行带 `!`，状态栏给失败计数 |
| 勾选的窗口被关掉 | 下一次刷新从选择里移除，状态栏说明"已关闭"（不是"移走"） |
| 列表为空 | 显示占位提示而不是空白 |
| 屏幕太窄放不下两列 | `computeLayout` 返回 false，状态栏说明宽度不足，停留在总览 |
| 平台命令未接入 | 明确说"等待 A 的接口"，绝不假装成功 |

## 动画（M4）

| 过渡 | 做法 | 时长 |
| --- | --- | --- |
| 打开总览 | `windowOpacity` 0→1，`OutCubic` | 180ms |
| 桌面 ↔ 排列画面 | 画布整体淡出 → 换数据 → 淡入 | 110 + 170ms |
| 收起总览 | 淡出后最小化（全局热键未接入时） | 140ms |

收起用"最小化"而不是"隐藏"：全局 `Ctrl+Alt+M` 由 A 注册，现在没有。真 `hide()` 会让窗口从任务栏消失且叫不回来，这正是交接文档警告的"操作后用户找不到窗口"。接入后加 `--allow-hide` 即可切成真隐藏。

## 手工测试步骤

```bat
run-fake.bat
```

1. 任务栏 4 行，右半屏是一整块桌面画面，窗口按真实位置叠在一起。
2. 勾「未命名 - 记事本」→ 右下角浮出「定位」；画面里那一块描蓝边。
3. 勾第二个 → 画面淡出淡入，切成左右分列；右下角变成「等宽 / 左 60 右 40 / 返回 / 确认排列」。
4. 切换比例 → 左右两块宽度立刻变化（不再淡入，要的就是马上看到）。
5. `Ctrl+Enter` → 回到桌面画面，两个窗口已经在新位置上，状态条写"排列完成"。
6. 勾第三个 → 只有两个保持勾选，状态条说"已替换"，画面换成新的一对。
7. 只勾「设置」→ `Enter`（或点「定位」）→ 红字提示被系统拒绝，该行出现 `!`。
8. `Esc` 在排列画面返回桌面；在桌面画面收起（最小化到任务栏）。
9. 真实模式：`run.bat`，能看到当前桌面的真实窗口（最多四个）；勾两个 → 确认，两个窗口真的被摆到左右。

## 界面结构（2026-10-20 全屏改版，PR #1）

```
┌──────────────┬──────────────────────────────────────┐
│ ☐ 标题        │                                      │
│   进程名 [预览]│     整个桌面（窗口按真实位置重叠）        │
│ ──────────── │            ┌───────────┐             │
│ ☑ 标题        │            │  浮窗      │             │
│   进程名 [预览]│            └───────────┘             │
│ ──────────── │                        [等宽][确认排列] │
└──────────────┴──────────────────────────────────────┘
```

- **无边框 + `showFullScreen()`**：这不是一个"应用窗口"，是盖在桌面上的一层总览。
- **左边一条任务栏**：每行 = 勾选框 + 标题/进程名 + 紧跟文字的预览。行高按窗口数均分
  （76–260），把整条任务栏铺满，不在下面留一截空。
- **右边一整块画布**：画的是"桌面上现在有什么"。不勾选时就是当前桌面；
  勾满两个，同一块画布切成"排完之后的样子"。
- 操作条和状态条**浮在画面上**，不占布局；没有可点的东西时整条隐藏。
- 列最多四个窗口（按面积从大到小），并跳过桌面壳层与输入法宿主。

四个必须讲清的决定（这一版新增）：

1. **为什么去掉了"排列"按钮**
   勾满两个窗口就自动切到排列结果。用户不用先找按钮，勾完就看见答案——
   这正是这个工具要说的话。只有"确认 / 返回 / 比例"才需要按钮。

2. **为什么画布不做等比缩放**
   左边任务栏吃掉 22% 宽度后，等比缩放在 1536×960 屏上会让画面上下各空 155px 深色边，
   看起来像"没渲染完"。改成 x/y 各自缩放铺满：左右占比（这个界面唯一要说的信息）
   在横向上，完全不失真；纵向被拉伸约 1.3 倍，换来整个桌面铺满屏幕。
   只有画布被挤成极窄一条（`scaleY/scaleX > 2.2`）才退回等比，免得多窗口被拉成面条。

3. **为什么自己画行，不用 `QListWidget` 的图标**
   Qt 的图标永远在文字左边，而这里的语义是"任务名字后面跟着它的画面"。
   `WindowRowDelegate` 自己画勾选框、文字、预览三块，顺序不受控件约束。

4. **为什么只有勾选框能勾选，点行其它地方不行**
   双击 = 定位，而双击会先后产生两次 `MouseButtonRelease`。整行可勾选的话，
   双击就是"勾上又取消"，用户看到的是"双击完全没反应"。
   所以判定区域只留勾选框（比画出来的方框大一圈，方便点）。

还要记住一条边界：`computeLayout()` 是 B 的函数，契约写死"恰好两个窗口"。
单窗口不经过它——那种情况下界面直接把这块画面描蓝边，不假装有一个"单窗布局算法"。

## 平台命令层（2026-10-20 补）

之前「定位」和「确认排列」在真实模式下只会回一句"等待 A 的接口"，因为 A 的
`Win32ApiAdapter` 只有查询、没有命令。现在补了一份兜底实现：

| 文件 | 位置 | 归属 |
| --- | --- | --- |
| `src/platform/windows/win32_window_commands.*` | 平台层 | **A 的地盘**，A 接好适配器后直接删掉 |
| `src/ui/live_service.cpp` 里的两处调用 | 界面层 | 只调服务接口，没有 windows.h |

三个实现要点（答辩可以直接讲）：

1. **置前要先还原**：`IsIconic()` 判断是否最小化，是就先 `SW_RESTORE`；否则
   `SetForegroundWindow` 对一个最小化窗口不会产生用户可见的效果。
2. **前台锁定要兜底**：Windows 只允许"当前前台进程"把前台权交出去，被别的进程
   抢过焦点就会失败。兜底是 `AttachThreadInput` 临时挂到目标线程的输入队列上，
   借它的权限完成置前。
3. **`SetWindowPos` 返回 true 不等于成功**：提权窗口、部分商店应用会"调用成功但
   拒绝执行"。所以摆位后必须 `GetWindowRect` 回读一次，偏差超过 2px 就判定失败。

真机验证 `tests/win32_commands_smoke.cpp`（7 项断言，全部通过）：

```
PASS 找到真实目标窗口
PASS place() 返回成功
PASS 系统里窗口矩形确实变成了目标值 | left=120 top=140 w=900 h=620
PASS activate() 返回成功
PASS 前台窗口确实变成了目标窗口
PASS 对不存在的句柄返回失败而不是崩溃
PASS 失败时给出了可读原因
```

## 构建踩坑：MSVC 必须加 /utf-8

源码里的中文注释是 UTF-8，MSVC 默认按 GBK 读。GBK 把 UTF-8 的多字节序列拆错后，
严重时一个中文字节会把行尾换行吃掉，让下一行代码并进注释，报出
`语法错误: "public"` 这种和代码完全对不上的错误。`CMakeLists.txt` 里已加
`add_compile_options(/utf-8)`，同时保证中文字面量按 UTF-8 存进 exe（否则界面会花）。

## 三个答辩追问题

1. **界面怎么知道窗口被关了？**
   下一次 `refresh()` 的快照里找不到这个 id。判断依据是"它在不在整份快照里"，不是"它从这一行消失了"。

2. **`layout_math.cpp` 为什么单独一个文件？**
   它属于 B 的职责（布局规则）。抽成无 Qt 依赖的纯函数后：能被单元测试直接调用、换 B 的实现只改这一处、界面不含任何比例常数。

3. **预览画布为什么不自己修正矩形？**
   画布只做"缩放 + 摆放"。如果比例不对，那是 B 的输入错了；界面偷偷修正会把问题藏起来，出问题时说不清是谁的责任。
