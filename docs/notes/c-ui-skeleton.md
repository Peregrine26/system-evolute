## 四个必须能讲清的点

**1. 为什么必须有 `set(CMAKE_AUTOMOC ON)`**
`Q_OBJECT` 宏会让类需要一个由 moc 生成的 `xxx.moc`。没有它，编译能过但链接会报 `undefined reference to vtable for ...`。这不是代码写错，是构建系统没给 moc 交活儿。

**2. 信号槽到底怎么把"点按钮"变成"界面更新"**
`QPushButton::clicked` → 我们连的 lambda → `service->switchWorkspace(id)` → 服务内部改状态 → `emit snapshotChanged(...)` → 界面 `applySnapshot()` 重建。**界面从不自己推断状态，只负责画服务给的东西。**

**3. 为什么 `snapshotChanged` 用 `Qt::QueuedConnection`**
如果用直连，点击按钮的瞬间就会同步重建顶部条，把**正在处理点击的那个按钮**删掉——这是典型的自删崩溃。队列连接让重建排到当前事件之后。配套代价：自定义类型必须 `qRegisterMetaType`，否则运行时信号被静默丢弃。

**4. 刷新时选中项怎么处理**
重建列表前记住 `m_selectedWindow`；重建后按 id 找回。找不回说明窗口已被外部关闭，于是**清除选择并提示**，绝不把下一条命令自动转给相邻窗口。

## 失败路径在哪

- 受限窗口：`ControlState::Restricted`，点它会返回失败提示，不假装成功。
- 迁移受限窗口：归属改变但显示状态未完成，`failureMessage` 同时表达两件事。
- 窗口消失：`simulateWindowClosed()` 可手动触发，验证选中清除。
- 操作返回 ≠ 成功：真正的结果走 `operationFinished`，界面只认它。

## 第二批：移动归属

**1. 快照从"只有当前页"改成"全部窗口 + 当前页是哪个"**
原来 `currentWindows` 只有当前工作区的窗口，于是窗口挪走和窗口被关闭在界面上长得一模一样。现在 `windows` 是全量，界面按 `workspaceId` 过滤出当前页，才能给出两种不同提示。

**2. 单击只选中，双击或回车才跳走**
文档写的是"选中窗口时总览收起并回到它"，但那样就没法"先选中、再移动"。所以这里拆成两个动作：单击 = 选中（底部按钮变可用），双击/回车 = 跳过去。**这条与文档字面冲突，需要和 B 确认后再定稿。**

**3. 移动菜单**
底部「移到其他工作区」按钮 → 弹出只含其他工作区的菜单 → 选中后调用 `moveWindowToWorkspace`。快捷键 `Ctrl+M`，所以全程可以不碰鼠标：Tab 到按钮、空格打开菜单、方向键选、回车确认。

**4. 挪走和关闭必须分开说**
移动成功后该窗口会离开当前页，选中必然失效。界面回到快照里找这个 id：还在（在别的工作区）→ 提示"已移到某页"；找不到 → 提示"窗口已关闭，选择已清除"。**同一个"选中项不存在"，两种事实，两句话。**

## 三个答辩追问题

1. **UI 为什么持有快照而不是指向窗口对象的指针？**
   因为窗口随时会关闭、句柄会失效。快照是一次性的只读事实，界面按 id 重新匹配；持有指针就会拿到悬空对象，或者不小心改到 B 的状态。
2. **服务返回"请求已发出"，界面凭什么说操作成功？**
   不凭什么。界面只在 `operationFinished` 且 `success=true` 时显示成功；平台调用返回只代表请求被受理。
3. **`main.cpp` 现在 new 的是假服务，将来换真服务要改几处？**
   一处：把 `FakeWorkspaceService` 换成真实实现即可，`OverviewWindow` 的构造参数类型是抽象基类指针。

## 第三批：查看所有窗口 + 空态 + 自动冒烟测试

**1. 「查看所有窗口」是一个 `QListWidget` 里的"分组列表"，不是两个列表**
点击后列表变成"全部工作区"，按工作区顺序排列，每组前插一行**不可选中**的表头（`Qt::NoItemFlags`）。好处：选中、方向键、双击激活全部复用同一套逻辑；坏处：表头不是真窗口，所以每行都要靠 `UserRole+1` 里的 id 判断"这行是不是窗口"。这是这批代码最容易讲错的一处。

**2. 移动菜单排除的是"窗口自己所在的工作区"，不是"当前显示的工作区"**
在普通模式下这两者相同，在全量模式下不同。如果按当前工作区排除，就会出现"把「学习」的窗口移动到「学习」"这种无效菜单项。

**3. 空态不是"什么都不显示"**
空工作区会插一行不可选中的占位文字，并让「移到其他工作区」保持灰色。用户看到的是"这里空着，可以移进来"，而不是"是不是卡了"。

**4. 调试菜单只在假服务下出现**
`qobject_cast<FakeWorkspaceService*>` 成功才挂上「调试（假数据）」按钮，可模拟"关闭选中窗口 / 清空当前工作区 / 重置假数据"。接 B 的真实实现后这个 cast 失败，按钮自动消失。**这是假数据阶段的临时脚手架，答辩时要主动说明，不要让人以为是产品功能。**

**5. 加了无界面自动测试 `tests/ui_smoke.cpp`（18 项断言）**
它在 offscreen 平台上真的构造窗口、点按钮、发命令，然后检查列表行数、行文字、按钮是否可用。`crossdesk_ui` 单独成库，就是为了让程序和测试编译同一份代码。

**6. 测试抓到一个真 bug（这条最值得讲）**
原来 `applySnapshot()` 的顺序是：先 `rebuildWindowList()`，再写"当前：某页 · N 个窗口"。结果列表刚设置的"选中的窗口已经关闭，选择已清除"**立刻被那句概括冲掉**，用户永远看不到关闭提示。修复方式是把概括写在重建列表之前，让更重要的提示有机会覆盖它。**这个 bug 靠肉眼看界面很难发现，因为文字在同一帧内被覆盖了。**
